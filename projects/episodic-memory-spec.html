Episodic Memory and Identity Anchoring: Technical Specification

A technical specification for an AI conversational state manager, detailing how episodic memory, identity anchoring, and retrieval-augmented context injection work together to create relational continuity in an LLM-based system.

Role
Technical writer, systems designer
Team
Solo project
Timeline
Developed alongside the River and Æsir system
Tools
Technical documentation, JSON schema design

The problem

Standard LLMs suffer from context drift: they forget earlier parts of a conversation or hallucinate details.

Documenting the solution meant writing for two audiences at once: a technical reader who needed to understand the implementation, and a design reader who needed to understand why the architecture decisions were made. Most system documentation chooses one and loses the other.

The document

The specification is structured as a versioned technical document with numbered sections, parameter definitions, and a worked example showing the full extraction, storage, and retrieval cycle for a single user input.

The comparison table between standard LLM behavior and the episodic system makes the value legible without prior technical knowledge. The document was written from inside the system: not as a description of something handed over, but as a record of something designed.

What it covers

  • Identity Anchoring: a static Anchor Profile with immutable Core_Values and a mutable Current_Mood that prevents character drift regardless of conversation length
  • Episodic Storage Logic: entity extraction, sentiment tagging, temporal stamping, and structured JSON storage for significant user inputs
  • The Retrieval and Context Injection pipeline: trigger conditions, semantic database queries, and response priming
  • A comparison table: a standard LLM (limited context window, linear recall, goldfish memory) against the episodic system (database retrieval, semantic tagging, relational continuity)

Sample and comparison

The specification includes a worked example that traces a single user input, "I really struggled with that meeting yesterday," through entity extraction, sentiment tagging, time-stamping, and storage, then shows how it surfaces in a future session when the user mentions work or stress. The comparison table comes from the document itself.
